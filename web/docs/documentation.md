# Maintaining the documentation

The short task pages are the main user path; detailed contracts live under Reference.
CLI help, schema tables, presets and downloadable templates are generated by
`web/scripts/docs_reference.py`. Edit templates under `src/dwarl/templates/`.

Regenerate the robot-neutral model illustration with
`MUJOCO_GL=egl pixi run python web/scripts/docs_examples.py`. Add `--test-directory`
with a testbot smoke-test directory to refresh the example trajectory.

The site is built from `web/docs/` with MkDocs. Search and navigation expose the
workflow; command help and resolved configuration are generated directly from
the implementation at build time. Update the walkthrough when behavior changes.

## Shared dashboard and documentation

`web/shared/theme.css` is the single source for branding, semantic palette
tokens, typography and the light/dark modes. The Vue dashboard imports this exact
stylesheet and the logos in `web/shared/assets/`; its small DaisyUI adapter maps the
shared tokens to component colours. Change the shared source, not generated CSS.

`pixi run web-build` builds the Vue frontend, then builds this same MkDocs site
into `src/dwarl/web/static/docs/`. `dwarl web` serves it at `/docs/` and displays the
generated articles inside the dashboard's native Documentation view. Its sidebar
and search reuse the built navigation and search index. Images, downloadable examples
and generated references come from the normal MkDocs build, with no second Markdown
renderer or duplicate page content. `web/scripts/docs_reference.py` publishes the shared
assets into the documentation build. These generated assets are ignored by Git
and included in wheels built after `web-build`.

Browser regression checks use an isolated workspace and a small MuJoCo scene:

```bash
pixi run web-build
pixi run npm --prefix web exec -- playwright install chromium
pixi run npm --prefix web test
```

They verify report images, native metric charts, documentation navigation/search,
and the real Studio WASM client, model download, UI/state WebSockets, reconnection,
and shutdown when the toggle or visible view is off. The test simulation host
has display access and offscreen rendering disabled.

Preview without installing the training stack (the slim `docs` pixi environment):

```bash
pixi run docs-serve      # mkdocs serve
pixi run docs            # mkdocs build --strict, as in CI
```

CI builds with `mkdocs build --strict` on every main push and pull request and
uploads a downloadable `documentation` artifact. This catches broken internal
links and keeps the generated reference in sync with code.

## GitHub Pages

To host the site, enable **Settings → Pages → GitHub Actions** and set the repository
Actions variable `PAGES_ENABLED` to `true`. Re-run Documentation or push to main.
Subsequent main pushes automatically deploy the site at <https://nobleo.github.io/dwarl/>.
Until then, use the CI artifact or local preview.
